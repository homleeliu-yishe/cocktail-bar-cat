# 有意思的酒单：公开吧台资料与时效协议（v2.6.2）

> 原 SKILL 第十四章。这里的「地图」指城市/店家文字索引，不自带地理底图、坐标或路线服务。公开第三方酒单快照知识与本机私有经营记录严格分开。

## 定位与数据

将公开可查、酒单本身有想法的吧台接进推荐链路。收录看酒单结构，不是有没有上榜。一杯要回答：哪家店、酒单怎么想、经典同源、大致怎么参考还原、往哪微调。

`bar_signatures.json` 保存79家店、16城市、57杯快照样本、26套酒单骨架、11种微调手法、46条公开来源；其中66家为独立/社区/主题概念店。历史建档检索日期为 **2026-11-17**，不因主包发版改成新查证日期；实时数量、月龄与分档用 `scripts/bars.py --stats`，不把建档分布当作今天统计。

触发：某家店那杯怎么做 / 别老给榜单大店 / 城市酒单 / 在地食材 / 这杯经典还能怎么升级 / 酒单换了吗 / 现在还有吗 / 看实拍酒单 / 一起共创。

## 14.1 从榜单转向酒单结构

v2.5.0只收10家榜单级别店；v2.6.0扩到独立小店与公开酒单思路。不评分、不排名，榜单只作带年份的背景；名气不等于味道好。

MIXY BAR的2017–2019故事叙事期与2026-05经典twist期几乎不重合。v2.6.1开始双期快照，旧6杯归历史，不能把一张多年以前的酒单说成永久招牌。其他可分析的思路包括 Evening Standard羊城风物、西厢区县×经典、16mm的Paloma改编、Set the Bar在地物产、Suma云南象限、慢宋黄酒Bamboo。

## 14.2 五条诚实边界

1. **不按榜单排序**：Asia's 50 Best/DMBA名次仅可选背景，提及时附年份。
2. **不评价好不好喝**：`taste_note` 与 `taste_disclaimer` 只摘录可追溯公开评价与争议，不改写成助手的实饮结论；长段评价不复制，兼顾来源权利。
3. **不是全国全量清单**：`coverage.not_exhaustive=true`；线下纸单、闭店、换址、换季都影响可查性。`known_gaps` 如实列缺口，不能因为某城未收录就说没有值得喝的店。
4. **不编配方**：`concept_only=true` 只给思路与骨架；有公开材料描述才可给按经典骨架推导的试做比例，明确「风味复刻/参考还原（非官方原方）」、`verified=false`。`confidence=low` 主动说明公开信息不足。
5. **不把某一期当永久招牌**：每杯带 `menu_snapshot/freshness/status/snapshot_source`；每店带 `menu_status/freshness/last_verified`。静态值仅建档基线，实际时效运行时算；换季/无酒单只给思路与结构。

商用先核店家许可或自行研发，不能因公开查到名称/材料就声称得到官方配方及商用授权。技术类标预处理时间，所有路线过甜度与食品安全闸门。材料可得性放末尾，不因在地食材缺失删除灵感。

## 14.3 文件四层

| 层 | 字段 | 回答 |
|----|------|------|
| 店家档案 | `bars[].menu_idea/why_interesting/menu_concept/ideas/tier/taste_note/concept_only/source_ids/source_date` | 酒单思路、店型、出处与争议 |
| 酒款快照 | `signatures[]` | 具体公开酒款及非官方试做方向 |
| 酒单骨架 | `menu_concepts[]` | 可以自行改编的整单结构 |
| 时效 | `freshness_policy/bars[].menu_snapshots/signatures[].menu_snapshot` | 哪一期、多久、换季及对照 |

每杯的字段链：`bar/city/source_ids` → `classic_anchor/anchor_note` → `replica` → `twists`（至少2个互相独立方向）→ `why`。锚点用当前 `recipes.json` 标准中文名；库里没有对应名则 `null`，用 `anchor_note` 解释结构，不硬凑。

## 14.4 十一种微调手法

| 手法 | 做法 | 注意 |
|------|------|------|
| 在地食材/风物志 | 用一个地方材料替经典一处 | 以结构连接，不虚构文化师承 |
| 浸渍/油洗/奶洗 | 预处理香气与质地 | 时间/温度/过敏及冷链明确 |
| 解构/澄清对照 | 同结构做质地对照 | 各半杯，标其他条件 |
| 风味冰/稀释时间线 | 茶/果汁风味与稀释变化 | 涉及多因素，不冒称纯单变量 |
| 预调/桶陈/发酵 | 批次一致性与风味研发 | 不用未知发酵工艺作家庭捷径 |
| 咸鲜入酒 | 海盐、可食用鲜味材料点睛 | 过敏、糖盐与材料差异 |
| 器皿叙事 | 杯具改变呈现 | 食品级/安全，不保证记忆效果 |
| ABV分级/尺码 | 低到高梯度或不同杯量 | 按实际度数计算，不鼓励全套饮用 |
| 命名系统/载体 | 编号、色彩、叙事等点单逻辑 | 主题要形成结构，不只文案 |
| 无酒单/客人自选 | 用户目标与材料驱动 | 先确认安全与口味，不上传偏好 |
| 持续换季/展览 | 围绕材料/季节做新一期 | 新一期不覆盖旧快照证据 |

完整数据：`python3 scripts/bars.py --levers`。与 `home.md` 的八旋钮联动；技术类尽量做基准/实验对照，不宣称未经实饮的口感。

## 14.6 查法速查

| 需求 | 参数 |
|------|------|
| 城市文字索引 | `--map` |
| 覆盖、缺口、实时月龄 | `--stats` |
| 一城 | `--city 西安` |
| 独立/店型 | `--independent` / `--tier 独立小店` |
| 在地食材等酒单思路 | `--idea 在地食材` |
| 只有概念 | `--concept-only` |
| 公开口味争议 | `--taste` |
| 单店/多期对照 | `--bar "MIXY BAR"` / `--snapshots "MIXY BAR"` |
| 过期/历史/分档 | `--stale` / `--archive` / `--freshness recent` |
| 换季/无酒单 | `--rotating` |
| 同经典的改编 | `--anchor 得其利` |
| 风味 | `--flavor 咸鲜` |
| 情绪 | `--mood 失落` |
| 结构/手法 | `--concepts` / `--levers` |
| 任意计算时点 | `--as-of YYYY-MM-DD` |

其他：`--list` 默认排除历史款；`--bars` 逐店档案；单词查询/`--json <酒名>` 查看原始结构。直接向用户推荐还须主文件安全与时效闸门，不能认为脚本过滤已经完整代替语义审校。

## 14.8 联动

情绪②路线至少1条、独立小店优先；酒单设计联动 `menu_concepts`；微创新联动 `twist_levers/twists`；新材料联动替换及家庭买酒；锚点遵循 `naming.md`。

## 14.9 照片、快照与换季（v2.6.1）

根因：把二手文字报道当永久事实，没有处理换季、客制化、闭店或换址；不是只改错了一杯。

### 三条硬规则

1. 每杯都是快照。输出日期与实时月龄；`aging/historical` 不作当前在售承诺，无日期为 `unknown`。
2. 默认排除历史款；`--archive` 才看历史；②路线优先近期且独立小店，不拿过期快照凑数。
3. `menu_status=rotating/no_menu` 只给思路，不列“必点”。MIXY BAR的2025-06公开媒体描述为 *menu changes constantly according to the owner's creative fancies*（中文对照：酒单随主理人的创作想法持续变化）；此引文须保留数据中的对应出处，不视为永久营业状态保证。

### 新酒单来源优先级

| 优先级 | 来源 | 注意 |
|--------|------|------|
| 1 | 店家当期官方酒单：公众号/官网/官方社交账号 | 记录发布日期 |
| 2 | 近期实拍酒单照片：商户相册、笔记、社区/推文配图 | 逐字读酒单，记录笔记发布日期，不把相册上传时间当菜单日期 |
| 3 | 近12个月消费者文字 | 旁证，不独立视为完整酒单 |
| 4 | 行业媒体/活动酒单 | 标明年/季/活动 |
| 5 | 两年以上报道 | 历史快照 |
| 6 | 榜单名次 | 背景，不作酒单证据 |

无日期一律 `unknown`；遵守平台登录/访问限制，不绕过反爬。v2.6.1审校记录中小红书/大众点评正文与相册未能直接抓取；这不是v2.7.2再次实测结果。当前能否读取须实际尝试，不把历史限制说成刚验证的平台事实。用户提供照片时保留日期角、先移除人脸/客户/付款及其他私人信息，并确认转交与引用权限。

### MIXY BAR双期快照

| 期 | 主题 | 证据用途 |
|----|------|----------|
| 2017–2019 | 故事叙事/杯具参与 | 历史样本，不作现在在售推荐 |
| 2026-05-01 | 经典twist，旁列经典 | 4杯低置信度样本，时效运行时重算 |

2026-05-01来自携程社区分享卡实拍中的日期和星期标识；材料与酒名公开，**比例未公开**，`confidence=low` 的复刻是经典骨架试做起点，非店家原方。

**第三方公开吧台价格的区别**：数据中有来源、日期的消费酒单价格（例如该期公开实拍 ¥108–138）属于第三方公开历史快照知识，保留其日期/来源并提醒不是当前价格，也不代表本技能采购、库存、成本或合成售价。不得据此给用户承诺消费价格、反推私有经营业绩或宣称市场行情。新投稿只记录来源实际公开的价格；无来源就留空，不造数字。

补录：追加 `{as_of,label,theme,drinks,prices,source_ids,freshness,note}` 到快照，在 `sources` 登记来源及日期；有材料再补酒款时效字段，运行 `audit.py` 并用 `--snapshots` 对照。授权与贡献流程见 `CONTRIBUTING.md`。

### 14.9.1 时效运行时计算（v2.6.2）

v2.6.1静态标签不能随时间变旧，v2.6.2由 `snapshot_date/age_months/classify/eff_freshness/eff_status/active_sigs` 实时计算。

| 项 | 口径 |
|----|------|
| 日期 | 完整日期优先；只有年份/年份范围时取最大年份1月1日保守估计 |
| 月龄 | `(计算日−快照日).days / 30.44` 向下取整 |
| 分档 | ≤18月 `recent`；18–48月 `aging`；>48月 `historical`；无日期 `unknown` |
| 计算日 | 默认运行当天；`--as-of YYYY-MM-DD` 覆盖 |

```bash
python3 scripts/bars.py --stats
python3 scripts/bars.py --as-of 2028-01-01 --stats
python3 scripts/bars.py --as-of 2026-11-17 --stats
python3 scripts/bars.py --as-of 2028-01-01 --list
```

JSON `freshness/last_verified` 为建档基线；查询、过滤、展示、情绪推荐用实时结果。`--stats` 展示基线与漂移，漂移是预期现象。门禁核日期可解析、无未来快照、JSON/脚本18/48阈值一致；不能改标签给旧酒单“洗新”。古书证据不套此月龄。

## 14.10 显式共创

静态包不会自动同步、回传或新增酒单。用户交来带日期、权限清楚的当期酒单 → 维护者审校 → 显式合并 → 门禁 → 中文更新说明 → 用户另行授权发布 → 使用者手动更新。

按 `CONTRIBUTING.md` 收齐店名/城市/日期及依据/可公开出处或照片/是否官方/是否换季/材料清单/署名；只给概念的店不编配方，旧期归档不删。发表前检查不含客户偏好、过敏、联系方式或经营记录；仅公开酒单资料可作投稿，不上传本机私有数据。
