# 经典历史证据与研发协议（数据层 v2.7.0）

> 按需读取：查询来历、最早酒谱、发明归属、原始配方、版次比较，或从历史结构创作酒单时。原 SKILL 第七章迁入本文件，核心证据闸门仍在 SKILL 主文件。

## 7.1 鸡尾酒故事查询

内容结构：可核到的文献记录（不是自动认定诞生）→ 归属/命名争议 → 原书版本与现代规格差异 → 不变的功能骨架 → 对客人的短讲解 → 可试做的改编启发。

先查 `cocktail_history.json`；再读故事的 `history_record_ids`。历史库优先于 `cocktail_stories.json`、配方 `story`、增强话术、流行品牌故事。故事未核的条目只给口感、结构与明确标注的传说，不输出精确创作者/发明年/名人引语。`quote` 默认是原创吧台文案，只有有原文出处的 `quote_en/quote_zh` 才能称史料引文。

## 7.2 故事推送

1. 读取 `push_history.json` 获取已推送列表；按 `recipes.json` 的 `aliases` 与历史库别名规范化比对（如「古典鸡尾酒」与「古典」），不因改名重复推送、不擅自重写既有记录。
2. 从 `cocktail_stories.json` 筛选未推送的，先按 7.1/7.3 历史证据闸门审校；未核起源不作确定故事推送。
3. 随机选择一款推送；只读脚本不更新记录。需持久化时由用户明确授权助手写入本机私有副本；全部推送完毕后先询问是否重置。
4. 公开包的推送记录默认空；不得将私人推送记录上传、合并或带入公开发版。

## 7.3 原始文献与版次：把家谱查清

触发：最古老的调酒书 / 最早出处 / 原始配方 / 谁发明 / Jerry Thomas / Oxford Night Caps / Savoy / 万变不离其宗。

按以下顺序读取与核查：
1. 先定位书名、作者、出版年、**具体版次**；记录 `sources.kind/verification`。`primary_transcription` 是原书数字转录，`institutional_excerpt` 是机构摘录，仍不同于亲眼核过扫描。`secondary` 是现代研究，`catalog_only` 只能证明书目存在。
2. 每个主张读 `claims.status`：`documented`（文献有记录）、`supported_secondary`（二手研究支持）、`disputed`（有争议）、`unverified`（未核）。定位优先「印刷页码 + 配方编号/标题」，没有页码就用条目标题/章节，不编页码；扫描页号另记，不能混用。
3. 分开五件事：词的出现、词的定义、同名配方的出版记录、结构前身、发明归属。使用「本库已核到的×年记录」「至少在×年已见此版本」，不要用「全球最早」「肯定发明于」。书中收录不代表作者发明；相似结构不证明直接师承。
4. 读取 `historical_versions` 原始材料和操作；现代出品来自 `recipes.json`，并排展示，不覆盖原始酒谱、不把现代规格标为原方。
5. 提炼功能，而不只抄材料名：基酒承担骨架，糖承担甜味及质地，苦精承担香气/轮廓，水与冰控制稀释；酸/芳香葡萄酒/草本/气泡按家族承担不同作用。六家族是**研发教学模型，不是穷尽一切的历史谱系**。

**已知书目边界**：1827《Oxford Night Caps》早于1862 Thomas 的职业调酒手册；v2.7.0审校时1827扫描平台仅返回标题，书目由历史书目与词典支持，**不能假装读到1827原方**。Thomas 的1862/1876/1887、Ensslin 的1916/1917、Johnson 各版各算一个出版证据；尤其1887 Thomas 为身后版，不能把其中晚出的配方倒记成1862年，也不能依据书名将作者当发明人。

## 7.4 原始单位、现代适配与安全

- 保留 `wine-glass / pony / dash / teaspoonful / table-spoonful / jigger / fraction` 原样；不强制换算毫升。旧 wine-glass、量勺、倒酒嘴容量和配方上下文会变，dash 也不是固定1ml。
- 若要实际复刻，先给「现代适配试做版（非原书精确换算）」；列换算假设、糖浆浓度、苦精品牌差异、酒精度与稀释口径。原书摇和、现代搅拌时明确是哪一步改了，不能偷偷把原书操作现代化。
- 不把 Bogart's/Boker's 等旧苦精与现代安格斯图拉当等价；gomme 与普通糖浆甜度和质地有差，Old Tom/Hollands 与现代伦敦干金也不同；旧芳香开胃酒名称不等于今天同名产品完全相同。
- 历史文献**不按酒单月龄过期**；新发现可以修正史实。吧台时效闸门只管现代门店是否在售，不用于删除古书证据。
- 不复制旧时代危险饮法：不点火饮用、不用吸管吸燃烧的酒、不以酒治病；有蛋/奶/坚果的原方要提示过敏、巴氏杀菌与冷藏。旧书里的大杯/大份不构成推荐摄入量。

## 7.5 万变不离其宗：历史 → 新酒单

**默认在原创特调、主题酒单和经典微改编中执行，不必等用户再次说“历史”。**

查一个历史锚点 → 写出 `structure/preserve` → 明确现代基准版本 → 从八旋钮选**一个**变量 → 基准/实验各半杯 → 写预期与风险 → 实饮后才调整下一处。

- 变体比较不是因果实验：两本书若同时改变基酒、糖、苦精，只叫版本差异。单变量实验需保持基酒总量、糖浆浓度/酸甜条件、稀释、温度、杯型等其他条件；不能一边改茶糖浆一边换冰或补糖。
- 糖浆替换按**近似等甜**而非机械等体积；没有糖度信息时注明尚未控制甜度，不能说纯粹测出了香气效果。柑橘换挡不默认酸度相同。
- 使用历史结构而不是虚构师承：日本鸡尾酒启发“带质地的甜味剂”；潘趣启发“茶作稀释/皮油进入甜味剂”；芳香酒家族启发“味美思负责可调的酒体”。创新保留的是作用，不强求材料或文化标签。
- 输出分两个层次：客人版1–3句来历/风味（有争议顺口说明）；研发版附书名版次与定位、保留功能、唯一改动、现代基准、试做量、预处理时间、成本与待验证状态。原创命名和诗意文案不能冒充旧书原名/历史事实。
- 酒单排法从 `menu_frameworks` 选：同一骨架的地方风味、同名酒的年代变化、六家族结构导航。每一款历史锚点必须是已核记录；另开无酒精路线，给独立名字，不宣称历史上已有。酒单不是一次喝完的挑战。

```text
酒名｜客人版：一句来历 + 一句风味（争议不藏）
证据：书名·具体版次·条目/页码｜已核记录/二手支持/争议｜来源链接
原书：原单位与原操作｜现代：出品库或注明适配假设
骨架：保留什么功能
创作：只改一处；基准/实验各半杯；预期；风险；待实饮验证
成本：运行时按当前合成价格或本机私有进价计算，并说明口径
```

## 7.6 只读查询入口与维护

```bash
python3 scripts/history.py --list
python3 scripts/history.py --sources
python3 scripts/history.py 马提尼 --compare
python3 scripts/history.py 飞行 --compare --creative
python3 scripts/history.py --family sour --creative
python3 scripts/history.py --menu
python3 scripts/history.py --stats --json
python3 scripts/history.py 古典 --json
python3 scripts/history.py --validate
```

脚本只读取本地证据并打印，不联网、不写盘、不自动学会新史料。缺文件/未收录时明确降级，**不要回退旧故事断言**。维护时对新材料执行「查原文/标题页 → 来源分级 → 短引文与中文 → 原单位/版次 → 创作桥 → 门禁 → 发版」。无法直接读原书的内容只能标二手；现代版权书只存必要短引文、书目和研究摘要，不整本复制。

## 7.7 第三方文献与权利边界

- 区分书目事实、必要短引文、维护者自行整理的摘要与创作分析；附原作者、书名、版次、定位、来源及可核到的许可信息。
- 短引文并非天然无限授权；引用目的、长度、使用方式与适用法域仍需独立审查。不复制受版权保护的整书、长段正文或未经许可的扫描/照片。
- 公有领域古书原文、数字平台转录、现代译文、版式、扫描图与网站内容可能具有不同权利状态，不因原书年代久远就给所有载体统一授权。
- 英文交付附中文对照；`quote_zh` 为对照译文时注明译者/自行翻译，不冒充权威版本。
- 本包尚未由用户指定许可证；公开可读不等于统一开源授权，不擅自授予 MIT 等全包许可。各来源许可、转载及商用条件需独立核查。
